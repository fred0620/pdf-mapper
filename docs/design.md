# 設計決策

記錄「為什麼這樣做」，給接手的人看。改變決策時更新這份文件，並在 commit 說明原因。

## 範圍
- 第 1 層建立範本（重點是 UI）、第 2 層解析輸出 Excel。第 3 層客製化不在範圍內，只保留 `workspace/custom/` 接口。
- 使用者是一般人，雙擊 `run.bat` 啟動，只在本機執行。
- 不限報關單，靠範本支援任何 PDF：有標題的值、只有值、會變長且跨頁的表格。

## 主要決策
- 來源：文字層優先，沒有內容或是亂碼才用 OCR。
- OCR：rapidocr（內建 PP-OCRv6 模型，安裝後不用連網）。
- PDF 讀取：pdfplumber + pypdfium2，避開 PyMuPDF 的 AGPL 授權。
- 對位：定位點依影像比對、文字層、OCR 的順序尋找，再算出平移、縮放、旋轉。
- 第 2 層只忠實取值，格式轉換交給第 3 層。
- 有疑慮就標記，不猜測。人工修正會保留原值。

## 介面
- 視覺採用 Stageshow（benjitaylor/skills stageshow/kit，MIT）的色彩、圓角、陰影與元件尺寸，全部寫在 `app/pdfmapper/web/style.css`，開頭留來源註記。
- 只用系統字型與純 CSS，不下載字型或套件，避免被公司擋。class 名稱不變，改樣式不動 `app.js`。
- 強調色沿用 Stageshow 的藍 #3b82f6；狀態色：需檢查橘、缺值紅、正常綠、人工確認或修改藍。工具要長時間閱讀，字級維持 12.5px 以上。
- 左上角顯示版本號，使用者回報問題時能直接看到。
- 一致性以 Stageshow 為準（2026-11-13 review）：
  - 正在看的對象（頁面上的框、結果表格的格子）用強調色外框，和其他元件的焦點一致，不用黑框。
  - 有資訊的字（版本號、欄位類型）用 `text`，`text-faint` 只留給停用與佔位。Stageshow 的 `text` 對比約 4.3:1、強調色按鈕上的白字約 3.7:1，略低於 4.5:1；為了和設計系統一致不另外調深，之後若要調整，應該改設計系統本身。
  - 小標籤與鍵盤提示的圓角用 `radius-sm`。頁面上的框和頁面本身維持 2px：它們代表 PDF 上實際的範圍，圓角大會看不出角落的位置。
- 頁面縮小到寬度不足 640px 時，框上的名稱改成移到框上、選取或正在看時才顯示，否則名稱會互相重疊、蓋住內容。
- 檔案清單的摘要分開寫「N 項待檢查」和「M 個提醒」，N 要和右邊「待檢查 N 項」一樣；提醒是整份檔案的問題（範本不合、找不到定位點、加總不符）。
- 視窗寬度 1000px 以下三欄改成上下排時，頂端提醒放大視窗。
- 解析中每 0.5 秒查進度，只拿新完成的結果（`/api/runs/<id>?since=n`），不重傳已經拿到的；另開的表格視窗也一樣。

## 表格
- 表頭標記：上緣和分隔線跟著表頭移動，下緣留在原位，代表資料最低到哪裡。
- 表尾標記：往下找到後，在它上方結束表格。也可用結束文字。找不到時退回固定位置並標記。
- 分欄：以整段文字為單位，再依各欄靠左或靠右判斷跨欄內容的歸屬。
- 切列：可自動判斷項次在第一行或中間。中間時用相鄰項次之間最大的空白來切。
- 跨頁：一列由多個片段組成，全部收集後才套用換行、第幾行和格式檢查。項次在中間時，依「每一列都一定有這欄」判斷歸屬，無法判斷就標記。
- 舊範本維持原本的切列設定。

## 儲存格取值
- 預設整格保留。第幾行、開頭文字、正規表達式、空格分段、字距分段都是選用。
- 開頭文字是儲存格內的 key value，只取值，可選到行尾、第一個空白或下一個開頭。
- 開頭文字的比對要寬鬆：空白多寡不拘、標點可有可無、全形半形視為相同、不分大小寫；開頭後面的冒號、句點、等號略過，不帶進值。負號和 # 不算分隔符號。英數開頭不比對到單字中間（No 不對到 Note），找不到才放寬（ECCN5A992）。短開頭落在長開頭裡時改找下一個位置。
- 解析失敗一律留空，原始內容留在 raw，顯示在確認畫面和 Excel。不把整格內容塞進欄位。
- 必有的欄位要勾「每一列都一定有這欄」才會標記空白；整份都沒抓到時會提醒規則可能不對。

## 警示強度
- 原則：警示只標在實際受影響的輸出欄位。同一格拆成多欄時，看每個欄位的值實際用到哪幾行（第幾行取值就是那一行；其他方式看值用到哪些行的文字），不整列或整格連坐。
- 跨欄、搶同一欄：只有跨欄那段文字真的進到這個欄位的值才標記（互相包含、有 4 字以上相同，或值的頭尾接在那段的尾頭）。
- 搶同一欄全部自動判斷，不提供手動開關。三個條件都成立才標記，而且只標多出來的那段：該直欄沒有用字距分段；這欄平常一行只有一段（每頁多段的行少於兩成）；多出來的那段貼著分隔線（兩個字寬內），而且不是貼著這欄自己的對齊線。
- 這一列可能跨頁：值用到的行來自兩頁，或其中有推測併進來的行（整頁沒有項次、依必填欄位切開開頭）才標記。項次在第一行時，下一頁第一個項次上方必定屬於上一列，不算推測。
- 這頁開頭可能屬於上一列：值用到第一個項次上方的行才標記。
- 項次不連續是「提示」（issue 的 level 為 notice）：不把儲存格標成需檢查，不影響檔案狀態、範本挑選分數和待檢查數。相鄰項次至少六成是 +1 才提示，否則視為 ID，不提示。
- Excel 待檢查表與乾淨資料的整份檢查欄會標「提示」。

## 換基準範例與修改舊範本（2026-11-11）
- 範本座標屬於建立時的基準範例。開舊範本、換基準、移除基準後由下一份接手時，都用解析時同一套定位點對位（`/api/rebase`），不另寫一套邏輯。
- 每頁只用定義在那一頁的定位點，沒有時才用頁面規則適用的。對位好的頁面自動換算；只找到部分定位點時先詢問；對不上或沒有定位點時框線不動並提示。打開不相關的範本會落在「對不上」，不會亂移。
- 儲存採「一次換算」：換算當下把座標改成新基準的座標，並立刻從新基準重抓定位點圖塊，之後照常編輯。不存「原座標加偏移量」，避免每換一次基準就疊一層誤差、解析時多一條路徑。移動不到 0.002 視為同一份，不改座標也不重抓圖塊。
- 新基準頁數比較少時，沒有的頁面保留原本的座標與圖塊（`finalize` 不再拿最後一頁頂替），左側與欄位清單會提示；要修改那幾頁時換一份頁數夠的範例。
- 沒有對位的頁面（對不上、或使用者選擇不套用）保留原本的圖塊，只有被拖動的框才重抓。
- 換算後清掉舊的測試結果，請使用者重新測試，格式真的不同的地方（分隔線、跨欄）仍靠測試標記。
- 草稿：只保留未儲存的修改，重開時先詢問要不要接著做，不自動套回。已儲存或空白的範本不保留。

## 人工確認與處理紀錄（2026-11-12）
- 參考 data-processor：處理過的警示不消失，留下紀錄。值第一次被處理前，把原本的狀態與原因存在 `flag`，原值存在 `original`；確認、修改都看得出「原本為什麼要檢查、後來做了什麼」，也能還原（`revert`）。
- 顏色規則和 data-processor 相同：橘色需檢查、紅色缺值、藍色是人確認或修改過的。結果表、PDF 上的框、Excel 都照這個規則。
- 任何值都能修改，不限有警示的：結果表按兩下就地修改，或點選後在右欄修改。改回原值時，有警示就當作確認，沒有就回到原狀。
- Excel「待檢查」也列出已處理的項目，「狀態」寫原本的狀態，「處理」寫確認或改成什麼。

- 驗證不符（加總、頁數）的整份疑點記下它連著的值（`ref`）。那個值確認或修改後，疑點標成已處理（`resolved`），不再算進待檢查與檔案狀態；還原後回到待處理。畫面以灰色「已處理：」保留原訊息，Excel 的狀態寫「已處理」，方便回頭查。（2026-11-21）
## 另開視窗核對（2026-11-12）
- 解析畫面的 PDF 與結果表格可以各自移到新視窗（`/?popout=pdf`、`/?popout=table`），方便兩個螢幕對照。
- 視窗之間用 BroadcastChannel 同步選取、檔案、頁數與修改；資料都在本機程式，新視窗自己去拿，不經過網路。
- 主視窗關閉或重新整理時，新視窗跟著關掉，避免看著過期的結果；新視窗關閉時主視窗自動收回。新視窗不提醒「尚未匯出」，關掉不會遺失資料。

## 畫面測試（2026-11-12）
- `tests/ui` 用 Playwright 在本機啟動工具並實際操作：處理紀錄、就地修改、單格 hover、兩種另開視窗、開舊範本對位、草稿詢問、新手導覽兩條關卡、說明選單、新功能導覽。頁面有任何錯誤就失敗。
- 儲存格可以有多行，每個能修改的地方（待檢查、表格就地修改、右欄選取、另開視窗）都測：打開時是完整內容且不用捲動、沒改按 Enter 不算修改、Shift+Enter 換行、處理紀錄與 Excel 保留換行。比對前把 `\r\n` 統一成 `\n`，textarea 會自動轉換，沒改的多行內容才不會被當成修改。
- 用電腦上已有的 Edge 或 Chrome（`channel`），不另外下載瀏覽器；playwright 放在 `ui` 群組，不在 dev，CI 映像檔沒有瀏覽器所以不跑，發版前在自己的電腦執行。
- 頁面的 CSP 不允許 eval，測試等待條件一律用 `expect`，不用 `wait_for_function`。
- 什麼時候跑：一輪修改告一段落時跑一次，不是每改一個檔案就跑（一次約 1 分鐘）。`scripts/ui_check.py` 記下上次通過時 `app/pdfmapper`、`tests/ui` 等檔案的雜湊，沒變動就略過。Claude Code 的 Stop hook（`.claude/settings.json`）在每輪結束時呼叫它，沒過就把錯誤交回給 Claude 繼續修；修過一次仍失敗就不再擋，交給人判斷，避免無限循環。找不到瀏覽器而整組跳過時不算通過。規則也寫在 `CLAUDE.md`，沒有 hook 的環境照樣適用。

## 新手導覽與新功能（2026-11-21）
- 三層入口：新手（起點歡迎畫面與實作關卡，主動出現）、進階（頂列「說明 ▾」與右欄設定旁的 ?，使用者找得到但不打擾）、新功能（升級時說明按鈕上的小點）。「說明 ▾」不論導覽開關都在，關閉導覽後進階功能不會消失。
- 統一成一個 Spotlight 引擎（`app/pdfmapper/web/spotlights.js`）：新手關卡、進階功能、觀摩範本、新功能都是同一種步驟資料，定位、捲動、高亮與浮動卡只有一套。用一般 `<script src>` 載入，不用模組或建置步驟，維持 CSP。
- 推關跳到第一個未完成的步驟，不是 +1；使用者主動回頭看時不拉走。「下一步」可以跳過，標成已跳過但不算完成。解析 PDF 第 2 步不用「處理過」當完成條件，第 3 步要看見藍色處理紀錄 600ms 或按過還原，否則還原的教學會被跳過。第 4 到 6 步做過一次就算完成。另開視窗的選取與修改同步回主視窗後一樣重算。
- 導覽的顏色分兩種（A4，2026-11-23 修訂）：導覽本身的介面（指令條、進度點、浮標、說明卡裡的控制項外框）用 Stageshow 唯一的強調色 accent；疊在 PDF 與結果表格上的指示（畫布虛線靶框、切欄線、儲存格外框）維持深色。原本全部用深色，是怕和代表「已人工處理」的藍色混淆，但使用者試用後反映中央上方的步驟區太不顯眼、黑色不是好選擇。混淆只會發生在 PDF 框與結果表格上，所以只有那裡保留深色；指令條換步驟時 accent 外圈脈衝一次，讓人注意到內容變了。「說明」按鈕維持深色字。
- 同一時間只有一個強調點：虛線靶框優先，其次是浮標，沒有浮標文字時才用外框；浮動卡開著時浮標退讓。進入新步驟時外框脈衝 2 次後靜止，減少動態的地方不動。
- 示範資料放在 `app/pdfmapper/demo/`（A6）：隨 app 更新、使用者刪不掉，由 `/api/demo-samples` 回傳，不依賴 `workspace/templates` 的示範範本（那份只在第一次建立時放入，刪了不會再出現）。檔案從 `app/samples` 與示範範本複製（`scripts/build_demo.py`），測試會確認兩邊一致。`mode` 只接受伺服器端白名單（train、run、showcase），不接受路徑；複製進上傳暫存後照樣檢查頁數與損壞；日誌只記 mode、doc_id 與數量。
- 示範不汙染正式資料（A7）：示範解析由伺服器固定用內附範本，帶 `demo` 標記，不算進最多 20 次的解析紀錄，只留最新一次，關閉示範文件時刪除；匯出檔名加「示範_」（`workspace/output` 照樣留一份）；練習範本預設叫「商業發票（練習）」，完成時可以刪除，伺服器只允許刪名稱以「（練習）」結尾的範本；觀摩範本唯讀，儲存一律另存成自己的範本。改用示範前未儲存的範本另外收著，左欄可以接回來。
- 進階功能卡（2026-11-23 修訂）：使用者試用後反映標題是功能名、看不懂要做什麼，也完全沒有正規表達式的說明。改成目標導向：標題寫「想做的事」，卡片固定是什麼時候用、例子（原始內容 → 抓到的值，用等寬字）、動作列（帶我去設定、試試看、看手冊 ↗）。從選單打開只開說明卡，按「帶我去設定」才切畫面；複雜的項目（明細接到下一頁）是 2 到 3 步的小導覽，做到了自動跳下一步。選單依分頁分組（抓值／表格／檢查與輸出、核對／瀏覽／匯出）。新功能導覽用同一種卡片。
- 規則試算的結果由後端算（`/api/regex-try`），用和範本取值相同的 `shape_value` 與相同的安全檢查，不在前端用 JS RegExp：兩邊的語法不同，試得出來的規則解析時可能對不上。規則有問題回 `ok: false` 而不是錯誤碼，頁面照常顯示說明；日誌不記規則與內容。從某一欄或欄位的設定打開時可以「套用到這一欄」。
- 「看手冊」連到使用手冊裡明寫的錨點（`{#id}`，`attr_list`），不依賴中文標題自動產生的 id（例如 `4.4` 會變成 `44`，改標題就壞）；測試確認每個卡片的錨點都存在。
- 數字檢查表單（2026-11-23）：使用者不知道三個下拉各要選什麼。表單上方說明檢查在做什麼、底部用白話預覽這條檢查或還缺哪一格，缺欄時「加入檢查」停用並用 title 說明，取代按了才跳的錯誤提示。新手導覽第 7 步拆成子步驟，由表單草稿推算，不另存狀態。
- 導覽細節（2026-11-23 第二次試用回饋）：
  - 指令條顯示時收起工具列原本的提示列，兩條藍色說明不疊在一起；導覽關閉或沒有進行中的步驟時照常顯示。提示列的舉例在示範發票時用發票的欄位，一般模式改成不綁特定單據的說法。
  - 示範發票的表格叫「明細」，切好的直欄用 PDF 上對應的標題命名（序號、品項、數量、金額），指令就能寫「表格欄選『明細：金額』」。對應方式是看直欄中心落在示範範本哪一欄，不直接讀標題列文字：示範發票的「品項」標題印在序號欄上方，直接讀會把序號欄叫成品項。只改還是「欄N」或之前自動命名的欄，非示範模式維持原本的「表格N／欄N」。欄名仍是「欄N」時，指令與提醒加上位置說明（最右邊那欄）。
  - 選錯提示用警告色加 ⚠，不用紅色：紅色在這個工具代表缺值。導覽裡其他地方沒有用到 danger 色系（圖例的「缺值」本來就是紅色）。
  - 浮標依序試目標的右、左、下、上，選第一個放得下、又不蓋到導覽列與指令條的位置。
  - 實地試用修正（2026-11-23）：每個步驟都要有看得見的指引（虛線靶框、浮標或外框），`tests/ui/test_guide_pointers.py` 逐步掃過 10 個練習與 2 個新手關卡。實地練習裡還有按鈕要先按時，先用浮標指到按鈕，進入框選模式後才換成畫布虛線靶框；原本兩者同時存在，浮標被虛線擠掉，使用者看不出要先按哪裡。最後的試抓步驟在選了表格或欄位時也繼續指著測試鈕。
  - 打字的步驟不能打第一個字就算完成：格式檢查與取值規則用練習的樣本驗證（能編譯、抓到預期的值、7 碼與 9 碼與前面多字都被擋住），還差什麼寫在提示列；範本名稱、開頭文字、輸出欄名在輸入框有焦點時要按 Enter 或離開輸入框才算，用「幫我填」或載入範本則有內容就算。
  - 規則試算的「換個例子」選了就留在選單上，不再歸零：歸零會讓用方向鍵或滾輪逐項切換的人永遠停在第一個例子（剛好就是預設的內容），看起來像沒有反應。
- 已有檔案或未儲存範本時重開導覽先詢問，可以在目前的 PDF 上繼續（不畫虛線靶框、完成條件放寬）。
- 進度存在 `localStorage` 的 `pdfmapper.onboarding.v1`，只存步驟 id 與旗標，不存 PDF 內容、檔名或抓到的值（和日誌原則一致）；讀取失敗一律當作新使用者。「關閉導覽」只收起導覽列，進度保留。
- 新功能寫在 `whatsnew.json`，只寫使用者看得到的改變。第一次使用的人不跳新功能；升級後小卡只出現一次，小點留到看過為止；新手導覽進行中只亮小點。發版時 `scripts/check_whatsnew.py` 檢查有這一版的條目，和 CHANGELOG 一樣沒寫不能發布。

## 多範本
- 先比定位點命中率，分數接近的再實際解析，選問題最少的。
- 比較時整個過程共用同一份開好的 PDF，文字層與影像辨識的結果在候選範本之間沿用。掃描檔用 3 個範本比較時，從約 30 秒降到約 9 秒，和只用一個範本差不多。
- 分數接近或全部對不上時要標記。Excel 依範本分工作表，避免相同欄位代號混欄。

## 輸出與資料處理邊界
- 判斷標準：需要 PDF 位置資訊的放 app，只看文字和業務規則的放 Power Query 或 Python。
- 規則放建立範本（含輸出欄位設定），匯出放解析 PDF，不另開功能。
- 檢查用 Excel 給人核對；乾淨資料給後續流程，固定保留來源、頁碼和檢查狀態。
- 未確認的資料預設保留在乾淨資料，由檢查狀態決定，可選只輸出已確認。

## 資訊安全（2026-11-09 review）
- 本機服務只接受 Host 為 127.0.0.1／localhost 的請求（擋 DNS rebinding）；`/api/` 拒絕跨站的 Sec-Fetch-Site 與不符的 Origin（擋 CSRF）。
- 回應加 CSP、X-Frame-Options、nosniff、Referrer-Policy、CORP/COOP；API 回應 no-store，頁面圖片只允許 private 快取。
- 錯誤只回一般訊息，例外細節寫進 `workspace/logs/pdfmapper.log`。`/api/ping` 只回路徑雜湊，不外洩本機路徑。
- 日誌原則：只記 doc_id、run_id、範本代號與數量；不記檔名（指令列用檔名雜湊）、PDF 內容、抓到或人工修正的值。輪替 1 MB × 5 份，30 天以上刪除。外部字串去控制字元，避免偽造日誌行。
- 上傳檢查 `%PDF-` 檔頭，檔名去掉路徑、控制字元與 Windows 不允許的字元；範本代號限 64 字並排除 Windows 保留名稱。
- 背景解析逐份 try/except，一份失敗不會讓整批卡在「解析中」；最多保留 20 次解析結果。
- Excel 所有文字儲存格統一去控制字元並強制文字格式（防公式注入，包含檔名與整份檢查訊息）。
- 啟動程式下載 uv 後比對官方 SHA256，不符就停止。升級 uv 版本時要同步更新雜湊。
- 處理上限（2026-11-10，回應外部 code review 3.1、3.2）：集中在 `app/pdfmapper/limits.py`。
  - 頁數上限 1000 頁，開檔時先數頁數，超過就不建立頁面資料。
  - 單檔時間上限 15 分鐘，在頁、欄位、表格之間檢查，超過只停這一份，其他檔案照常。多範本比較共用同一個期限。
  - 渲染圖整份文件最多留 6 張（原本每頁各留 2 張直到關檔，100 頁掃描檔做 OCR 約累積 2.6 GB）；單頁超過 4000 萬像素時自動降解析度。
  - 正規表達式（2026-11-13 修訂）：執行時一律走 `limits.search`，用 `regex` 套件設 1 秒逾時，逾時就停止這份檔案並說明是哪個寫法。原本只靠事前檢查、不加 `regex`，但 review 時發現外層有次數上限的寫法（例如 `(\d+[,.]?){8}元$`）會漏網，在 43 字的儲存格上就卡超過 20 秒；`re` 卡住時無法打斷，背景解析會永遠停在那份檔案，工具也不會自動結束。靜態檢查擋不完所有寫法，所以改成執行時保護。`regex` 在 PyPI 有各平台的預先編譯套件，uv 可以直接安裝，離線打包時一樣比對 `uv.lock` 的 SHA256，不增加發布負擔。
  - 範本儲存與載入時仍會先擋常見的危險寫法，提早請使用者改寫：外層可以重複 3 次以上（含無上限）、裡面又有重複、而且沒有固定字元隔開，例如 `(a+)+`、`(\w+\s?)+`、`(\d+\s?){6}`，並限 500 字。從 3 次開始擋是實測結果：`(\d+\s?){3}` 遇到 300 字要 8 秒以上，`{2}` 不到 0.3 秒。`(a|aa)+` 這類靠選項重疊的寫法事前偵測不到，交給執行時的逾時。
  - 範本的寫法要同時能被 `re` 和 `regex` 接受，兩邊預設語法相同。
  - 不做的：限制比對文字長度（儲存格本來就短，截斷反而會改變取值結果）；用子行程強制中止（每個行程都要重新載入 OCR 模型，Windows 上成本高）。
- 發布與更新的完整性（2026-11-10 review）：
  - 安裝新版前，ZIP 必須和同資料夾的 `SHA256SUMS*.txt` 相符（瀏覽器重複下載的核對檔都會找，任一份相符即可），詢問時顯示雜湊。擋下載不完整、拿錯檔案、改名冒充的 ZIP。採最小改動：核對檔和 ZIP 來自同一個 Release 頁，擋不住能改 Release 的人；要防這一層得加簽章，目前不做。
  - 打包時每個離線套件都要和 `uv.lock` 的 SHA256 相符，鏡像或 PyPI 上的檔案被換掉就不發布。同事端不另外 `--require-hashes`，因為清單和套件在同一個 ZIP 裡，已由 ZIP 的核對涵蓋。
  - 啟動用 `python -P`，工具資料夾裡的同名 `.py` 不會被誤載入。
- 保留現狀：匯出仍在 `workspace/output` 留一份（手冊既有功能）；`--post` 會執行指定腳本（第 3 層設計）。

## 發布、更新與資料夾分工（2026-11-10）
- 不包成 exe。PyInstaller 這類打包常被防毒誤判，每次啟動要解壓到暫存，也不能只更新一部分。資料夾加啟動腳本比較透明，IT 也容易審核。
- 資料夾分三塊：`app/` 是程式，更新整包換；`workspace/` 是使用者資料，更新不動；`runtime/` 放 uv、Python 與套件，可隨時刪掉重建。所有路徑集中在 `app/pdfmapper/paths.py`，啟動程式用 `PDFMAPPER_HOME` 指定最外層。
- `run.bat` 只有一行並以 `exit /b` 結尾。cmd 執行批次檔時是一行一行讀，整行讀完才執行，更新時覆蓋 `run.bat` 才不會接著讀到新檔案的內容。
- 發布走 GitLab Release。同事下載 ZIP 後不用解壓，直接放進工具資料夾，雙擊 `run.bat` 就會偵測並詢問安裝。這樣不需要共用資料夾，也不用在同事電腦存 GitLab token。
- 不做連網自動檢查：同事的電腦通常連不到需要登入的 GitLab，也沒有共用位置可放版本資訊。改成把手動步驟寫清楚，使用手冊附圖解，並保留自動換版失敗時的手動更新方式。
- 只在雙擊開啟時找新版 ZIP；指令列模式不檢查也不暫停，才能放進排程。
- 從網路下載的 ZIP 會被 Windows 標成「來自網路」。第一次安裝要使用者解除封鎖；之後由 `run.bat` 用 PowerShell 解壓安裝，不會再遇到。
- 安裝順序：解壓、確認版本與檔名一致，才把 `app` 改名成 `app.old`、新版移入。中途失敗就換回原狀。保留一份 `app.old` 給使用者自行 `rollback`。
- 全面退回不靠 rollback：啟動程式只會往新版更新，要讓所有人回到舊行為，就發一個還原修改的新版本。
- 要所有人更新或暫停使用時，由負責人直接通知。
- 發布包附 Windows 64 位元的套件檔（`app/wheels`），用 `uv pip sync` 讓環境和清單完全一致，舊版多出的套件會移除。使用者不需要連到 PyPI，只有第一次要從 GitHub 下載 uv 和 Python。
- 版本號只寫在 `app/pyproject.toml`。程式、啟動腳本、CI 都讀它；打標籤時 CI 會比對標籤和版本，CHANGELOG 沒有這一版的段落就不能發布。
- 0.1 版的 `templates`、`custom`、`output` 與 `.tools` 會在第一次啟動時複製或搬到新位置，只複製不刪除，由使用者確認後自行刪掉。
- 示範範本只在第一次建立 `workspace/templates` 時放入，使用者刪掉後不會再出現。
- 版本不一致防護（0.4.1）：只比版本號分不出同版號底下的不同程式（例如 0.4.0 後來併入實地練習），因此改用內容指紋（`build.py` 的 `compute_build_id()`，對 `app/pdfmapper/*.py`、`web/**`、`demo/**/*.json` 依路徑排序算 SHA256 取前 12 碼）。伺服器啟動時記下 `RUNNING_BUILD`，每次 `/api/status` 回傳 `build` 與快取的 `disk_build`，前端在啟動與 `visibilitychange` 檢查，不一致就顯示 `#updateBanner`（不擋操作、不用紅色），另開視窗也顯示；`/api/heartbeat` 連續失敗 3 次改顯示工具已關閉；之後 heartbeat 恢復成功（例如電腦睡眠後喚醒）就收起這則提示並重新比對指紋，避免伺服器其實還在卻一直顯示已關閉。第二次啟動在 `_pick_port()` 讀 `/api/ping` 的 `build`，相同就維持直接開瀏覽器，不同或缺少欄位時在互動主控台詢問 Y/N（非互動模式不詢問並以非 0 代碼結束）。關閉舊版走 `POST /api/shutdown`，沿用本機 Host、Origin 與 Sec-Fetch-Site 檢查，並額外要求 `X-Instance-Token` 標頭，與 `workspace/run/instance.json` 內的隨機 token 以 `hmac.compare_digest` 比對；瀏覽器頁面沒有這個 token 所以無法觸發，解析進行中回 `busy` 不強制中止，日誌只記原因不記 token。是否忙碌的檢查與「答應關閉」的標記（`_closing`）在 `_runs_lock` 裡一起完成，之後 `/api/runs` 一律回 503，因此回 ok 到行程結束之間不會有新的解析開始又被中斷。

## CI 與公司網路（2026-11-10）
- 公司 runner 常常連不到 pypi.org。`uv sync --frozen` 會照 `uv.lock` 記的 pypi.org 網址下載，設定鏡像也沒用，所以 CI 改成 `uv export`（含 SHA256）再 `uv pip install --require-hashes`，來源由 `PIP_MIRROR` 決定，檔案仍和 lock 完全相同。
- 每個 job 開頭用 `scripts/ci_env.sh` 先連一次套件來源，連不到就用中文說明要找 IT 要什麼，不讓使用者看到難懂的錯誤。
- 全部 job 只用一個映像檔（ghcr.io 的 uv）。上傳與建立 Release 改用 Python 標準函式庫（`scripts/publish_release.py`），不再拉 Docker Hub 的 curl 和 registry.gitlab.com 的 release-cli，要請 IT 放行或鏡像的東西只剩一個。
- `uv lock --check` 不需要網路，但設了鏡像時 uv 會因為鏡像網址和 lock 記的 pypi.org 不同而誤判要更新，所以檢查時暫時拿掉鏡像設定並加 `--offline`。
- 弱點檢查不放在 CI：資料庫在 pypi.org，公司鏡像沒有，一直失敗的 job 只會讓人習慣忽略紅燈。改成發版前與每月在自己的電腦執行 `scripts/audit.py`，列在發版檢查清單。PDF 是不受信任的輸入，pdfium、pdfminer、Pillow、OpenCV 都有過弱點，所以檢查本身不能省。
- 測試用的範例掃描檔要畫中文，CI 映像檔沒有中文字型。專案內附 Noto Sans CJK TC 的子集（`tests/fonts`，OFL 授權，只含範例與測試用到的字，約 190 KB），每台電腦和 CI 畫出來的範例都一樣。不打包進發布包。
- 沒有鏡像時的退路：在自己的電腦打包，手動建立 Release。

## 進階功能的實地練習（labs）
- 入口：進階功能說明卡的主要按鈕「實地練習」，原「帶我去設定」降為次要。沒有文件也能練。
- 引擎與新手關卡共用：步驟資料、指令條、浮標、虛線靶框、推關規則都是同一套，導覽的 view 叫 `lab`（`guideView()`）。步驟放 `web/labs.js`，練習 PDF、練習範本、步驟 id、驗證方式與預期值放 `demo/labs.json`。
- 最後一步不是自己宣告完成：呼叫既有的「用範例測試」，把試抓結果和 labs.json 的預期值比對（比對前 `\r\n` 轉 `\n`）。錯了指出哪一列差在哪裡，提示依 labs.json 的 `hints` 順序挑第一個符合的。最後一步不能跳過。
- 練習不碰使用者的工作：開始前把文件、範本、undo、選取等整組收起來（記憶體，不是草稿），回到我的工作時原樣放回。練習中 `saveDraft` 不寫 localStorage，所以原本的草稿不會被蓋掉；練習範本不能存檔，不寫入 workspace/templates，不做正式解析，所以不佔紀錄。
- `/api/demo-samples` 加 `mode: "lab"` 與 `lab`，id 以 labs.json 的鍵為白名單，未知 id 回 400，Host、Sec-Fetch-Site、Origin 檢查沿用。
- 進度只在畫面上，不存檔；只有「做完過」的 id 記在 `prefs.labsDone`，說明選單顯示「練習過 ✓」。
- 練習 PDF 用 `scripts/make_samples.py` 的 `build_labs()` 產生，只用英數字標題（字型子集缺字），底圖用灰階 PNG，十份合計要在 300 KB 內。
- 批次 B（練習 4 到 7）的驗證方式：`labs.json` 的 `verify.kind` 新增 `field_flag`（欄位值要被標上指定原因，用在格式檢查），`column` 可加 `per_doc: true`（`expect` 改成每份一組，位置不固定的練習用）與 `rows_hint`（列數不符時的專屬提示）。`pdfs` 與 `doc_names` 成對時一個練習可載入多份 PDF，第一份是基準範例；`verify.done` 可自訂完成畫面的結果文字。
- 表頭只讓表格上緣與分隔線跟著移動，範圍下緣不動，所以位置不固定的練習範本把範圍下緣拉到頁面底部；沒框表頭時第 2 份的表格會偏掉。
- 練習 PDF 要用 `.gitignore` 的例外（`!app/pdfmapper/demo/labs/*.pdf`）才會進版控，批次 A 漏了這行，這次一併補上。
- 批次 C（練習 8 到 10）：`verify.kind` 新增 `sum_check`（範本要有指定的「幾個欄位相加」檢查，且試抓後等號右邊的欄位被標上 `sum_mismatch`）、`output`（用 `outputColumns()` 算出的輸出欄名與順序要等於預期）、`run_templates`（解析結果每份用到預期的範本代號）。練習 8 的單據故意把 Total 寫錯（4,500 + 225 不等於 4,800），這樣才看得到檢查標出東西。
- 輸出設定原本沒有預覽，批次 C 在面板下方加「乾淨資料預覽」：`outputColumns()` 是伺服器 `clean.output_columns` 的前端版本，規則相同（沒列出的欄預設輸出、欄名留空用原名、重名加 `_2`），練習 9 的驗證與預覽共用它。預覽只列資料欄，來源、頁碼與檢查狀態固定附上。
- 數字檢查的「要相加的欄位」由複選 select 改成 checkbox 組（`#checkFields`），欄位順序依欄位清單，不依勾選先後。
- 解析 PDF 的練習在解析分頁進行：`labs.json` 的 `view` 為 `run`（前端在 `LAB_RUN_VIEW`），`guideView()` 與 `guideVisible()` 改用 `labView()` 判斷練習所在的分頁。練習範本不是 workspace 的範本：`/api/demo-samples` 只回傳範本代號與名稱，`/api/runs` 加 `demo: "lab"` 與 `lab`，範本只能從該練習 `templates` 挑（用各自的練習 PDF 補圖塊），不接受頁面傳來的內容，不佔解析紀錄、匯出檔名加「示範_」。左邊範本清單在練習中換成練習範本，結束時 `runDocs`、`run`、`templateIds` 與其他狀態一起放回。
- 取捨：練習 2 的標準做法是選「開頭文字」填 `ECCN:`，值到哪裡結束維持預設「這一行結束」；選做的「同一格拆成多欄」這一批沒做。

## 使用手冊改為參考手冊（2026-11-23）
- 原因：新手導覽與 10 個實地練習上線後，原手冊第 4 章約 190 行的逐步教學和導覽重複，兩邊會各自過時；使用者在工具看到的是說明卡標題，手冊卻用功能名與章號，搜不到。改成工具負責教、手冊負責查：手冊只放導覽教不到的規則細節、例外與出錯怎麼辦。
- 功能章節標題和 `FEATURE_SPOTLIGHTS`、`RUN_SPOTLIGHTS` 的 title 一字不差，依說明選單的分組排列。每節固定「什麼時候用、怎麼設、例子、常見錯誤、在工具裡練習」，例子用「原始內容 → 抓到」的表格，讀者跳進任何一節都看得懂。有實地練習的寫「說明 ▾ → 標題 → 實地練習」，沒有的寫「帶我去設定」或新手導覽的步驟。

- 安裝、更新、退回版本與離線安裝的步驟原樣保留；常見問題改依症狀（打不開、抓不到、抓錯、對位失敗、跑很慢）分組。新增「讓 AI 幫你設定」：工具不內建 AI，提供提問範本與這個工具的正規表達式規則，貼回試算區驗證。

## 治理
- 負責人、備援人、處理的資料與出問題時的做法記在 `OWNER.md`。
- 刻意只留大架構：工具卡、發版檢查清單、維護手冊。不寫各公司不同的政策或登記流程，公司另有規定時以公司為準。
- 每次發版依 `docs/security-checklist.md` 勾選；CI 自動做測試、`uv lock --check` 與打包驗證，弱點檢查在本機執行 `scripts/audit.py`。
- 發布權限：版本標籤設為受保護，只有負責人能建立 Release。

## 環境
- 用 uv 建立，uv、Python 3.12 和套件都放在 `runtime/`，不裝進系統 Python，也不需要先安裝 Python。
- 依賴定義在 `app/pyproject.toml`，版本鎖在 `app/uv.lock`。
- 發布包的離線套件走 `uv pip sync --no-index --find-links`，因為 `uv sync --frozen` 不吃 `--find-links`。

## 資源釋放
- 所有頁面關閉後程式自動結束，正在解析時會等解析完。
- 已開著時再啟動，只開啟原本的工具。
- 上傳的 PDF 暫存在結束時清除，異常結束則在下次啟動時清除。

## 待確認
- 真實資料：續頁版面、文字層品質、貨物名稱長度與跨頁列的實際行為。
- 同一格同一個 key 出現多次、一格多個 sub 要拆成多列：尚未支援。
- 影像型 PDF 的跨欄內容：逐欄辨識會切到長文字，目前只能標記。
- 分隔線整份都放偏時，吃進來的內容每一行都有，會被當成這欄的格式而不標記搶欄；目前靠隔壁欄空白或必填缺值發現。
- 值很短（一兩個字）時，用文字判斷值用到哪幾行可能誤認，偏向多標記。
- 結果表格的儲存格不在字中間折行，很長的中文貨名可能讓欄位變寬，要用真實資料看。
- 真正的 Windows：啟動與更新流程只在 Linux 版 PowerShell 測過。
