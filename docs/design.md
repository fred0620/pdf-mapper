# 設計決策

記錄「為什麼這樣做」，給接手的人看。改變決策時更新這份文件，並在 commit 說明原因。

## 範圍
- 第 1 層建立範本（重點是 UI）、第 2 層解析輸出 Excel。第 3 層客製化不在範圍內，只保留 `workspace/custom/` 接口。
- 使用者是一般人，雙擊 `run.bat` 啟動，只在本機執行。
- 不限報關單，靠範本支援任何 PDF：有標題的值、只有值、會變長且跨頁的表格。

## 主要決策
- 來源：文字層優先，沒有內容或是亂碼才用 OCR。
- OCR：rapidocr（內建 PP-OCRv6 模型，安裝後不用連網）。
- PDF 讀取：pdfplumber + pypdfium2，避開 PyMuPDF 的 AGPL 授權。
- 對位：定位點依影像比對、文字層、OCR 的順序尋找，再算出平移、縮放、旋轉。
- 第 2 層只忠實取值，格式轉換交給第 3 層。
- 有疑慮就標記，不猜測。人工修正會保留原值。

## 介面
- 視覺採用 Stageshow（benjitaylor/skills stageshow/kit，MIT）的色彩、圓角、陰影與元件尺寸，全部寫在 `app/pdfmapper/web/style.css`，開頭留來源註記。
- 只用系統字型與純 CSS，不下載字型或套件，避免被公司擋。class 名稱不變，改樣式不動 `app.js`。
- 強調色沿用 Stageshow 的藍 #3b82f6；狀態色：需檢查橘、缺值紅、正常綠、人工確認或修改藍。工具要長時間閱讀，字級維持 12.5px 以上。
- 左上角顯示版本號，使用者回報問題時能直接看到。

## 表格
- 表頭標記：上緣和分隔線跟著表頭移動，下緣留在原位，代表資料最低到哪裡。
- 表尾標記：往下找到後，在它上方結束表格。也可用結束文字。找不到時退回固定位置並標記。
- 分欄：以整段文字為單位，再依各欄靠左或靠右判斷跨欄內容的歸屬。
- 切列：可自動判斷項次在第一行或中間。中間時用相鄰項次之間最大的空白來切。
- 跨頁：一列由多個片段組成，全部收集後才套用換行、第幾行和格式檢查。項次在中間時，依「每一列都一定有這欄」判斷歸屬，無法判斷就標記。
- 舊範本維持原本的切列設定。

## 儲存格取值
- 預設整格保留。第幾行、開頭文字、正規表達式、空格分段、字距分段都是選用。
- 開頭文字是儲存格內的 key value，只取值，可選到行尾、第一個空白或下一個開頭。
- 開頭文字的比對要寬鬆：空白多寡不拘、標點可有可無、全形半形視為相同、不分大小寫；開頭後面的冒號、句點、等號略過，不帶進值。負號和 # 不算分隔符號。英數開頭不比對到單字中間（No 不對到 Note），找不到才放寬（ECCN5A992）。短開頭落在長開頭裡時改找下一個位置。
- 解析失敗一律留空，原始內容留在 raw，顯示在確認畫面和 Excel。不把整格內容塞進欄位。
- 必有的欄位要勾「每一列都一定有這欄」才會標記空白；整份都沒抓到時會提醒規則可能不對。

## 警示強度
- 原則：警示只標在實際受影響的輸出欄位。同一格拆成多欄時，看每個欄位的值實際用到哪幾行（第幾行取值就是那一行；其他方式看值用到哪些行的文字），不整列或整格連坐。
- 跨欄、搶同一欄：只有跨欄那段文字真的進到這個欄位的值才標記（互相包含、有 4 字以上相同，或值的頭尾接在那段的尾頭）。
- 搶同一欄全部自動判斷，不提供手動開關。三個條件都成立才標記，而且只標多出來的那段：該直欄沒有用字距分段；這欄平常一行只有一段（每頁多段的行少於兩成）；多出來的那段貼著分隔線（兩個字寬內），而且不是貼著這欄自己的對齊線。
- 這一列可能跨頁：值用到的行來自兩頁，或其中有推測併進來的行（整頁沒有項次、依必填欄位切開開頭）才標記。項次在第一行時，下一頁第一個項次上方必定屬於上一列，不算推測。
- 這頁開頭可能屬於上一列：值用到第一個項次上方的行才標記。
- 項次不連續是「提示」（issue 的 level 為 notice）：不把儲存格標成需檢查，不影響檔案狀態、範本挑選分數和待檢查數。相鄰項次至少六成是 +1 才提示，否則視為 ID，不提示。
- Excel 待檢查表與乾淨資料的整份檢查欄會標「提示」。

## 換基準範例與修改舊範本（2026-11-11）
- 範本座標屬於建立時的基準範例。開舊範本、換基準、移除基準後由下一份接手時，都用解析時同一套定位點對位（`/api/rebase`），不另寫一套邏輯。
- 每頁只用定義在那一頁的定位點，沒有時才用頁面規則適用的。對位好的頁面自動換算；只找到部分定位點時先詢問；對不上或沒有定位點時框線不動並提示。打開不相關的範本會落在「對不上」，不會亂移。
- 儲存採「一次換算」：換算當下把座標改成新基準的座標，並立刻從新基準重抓定位點圖塊，之後照常編輯。不存「原座標加偏移量」，避免每換一次基準就疊一層誤差、解析時多一條路徑。移動不到 0.002 視為同一份，不改座標也不重抓圖塊。
- 新基準頁數比較少時，沒有的頁面保留原本的座標與圖塊（`finalize` 不再拿最後一頁頂替），左側與欄位清單會提示；要修改那幾頁時換一份頁數夠的範例。
- 沒有對位的頁面（對不上、或使用者選擇不套用）保留原本的圖塊，只有被拖動的框才重抓。
- 換算後清掉舊的測試結果，請使用者重新測試，格式真的不同的地方（分隔線、跨欄）仍靠測試標記。
- 草稿：只保留未儲存的修改，重開時先詢問要不要接著做，不自動套回。已儲存或空白的範本不保留。

## 人工確認與處理紀錄（2026-11-12）
- 參考 data-processor：處理過的警示不消失，留下紀錄。值第一次被處理前，把原本的狀態與原因存在 `flag`，原值存在 `original`；確認、修改都看得出「原本為什麼要檢查、後來做了什麼」，也能還原（`revert`）。
- 顏色規則和 data-processor 相同：橘色需檢查、紅色缺值、藍色是人確認或修改過的。結果表、PDF 上的框、Excel 都照這個規則。
- 任何值都能修改，不限有警示的：結果表按兩下就地修改，或點選後在右欄修改。改回原值時，有警示就當作確認，沒有就回到原狀。
- Excel「待檢查」也列出已處理的項目，「狀態」寫原本的狀態，「處理」寫確認或改成什麼。

## 另開視窗核對（2026-11-12）
- 解析畫面的 PDF 與結果表格可以各自移到新視窗（`/?popout=pdf`、`/?popout=table`），方便兩個螢幕對照。
- 視窗之間用 BroadcastChannel 同步選取、檔案、頁數與修改；資料都在本機程式，新視窗自己去拿，不經過網路。
- 主視窗關閉或重新整理時，新視窗跟著關掉，避免看著過期的結果；新視窗關閉時主視窗自動收回。新視窗不提醒「尚未匯出」，關掉不會遺失資料。

## 畫面測試（2026-11-12）
- `tests/ui` 用 Playwright 在本機啟動工具並實際操作：處理紀錄、就地修改、單格 hover、兩種另開視窗、開舊範本對位、草稿詢問。頁面有任何錯誤就失敗。
- 儲存格可以有多行，每個能修改的地方（待檢查、表格就地修改、右欄選取、另開視窗）都測：打開時是完整內容且不用捲動、沒改按 Enter 不算修改、Shift+Enter 換行、處理紀錄與 Excel 保留換行。比對前把 `\r\n` 統一成 `\n`，textarea 會自動轉換，沒改的多行內容才不會被當成修改。
- 用電腦上已有的 Edge 或 Chrome（`channel`），不另外下載瀏覽器；playwright 放在 `ui` 群組，不在 dev，CI 映像檔沒有瀏覽器所以不跑，發版前在自己的電腦執行。
- 頁面的 CSP 不允許 eval，測試等待條件一律用 `expect`，不用 `wait_for_function`。

## 多範本
- 先比定位點命中率，分數接近的再實際解析，選問題最少的。
- 分數接近或全部對不上時要標記。Excel 依範本分工作表，避免相同欄位代號混欄。

## 輸出與資料處理邊界
- 判斷標準：需要 PDF 位置資訊的放 app，只看文字和業務規則的放 Power Query 或 Python。
- 規則放建立範本（含輸出欄位設定），匯出放解析 PDF，不另開功能。
- 檢查用 Excel 給人核對；乾淨資料給後續流程，固定保留來源、頁碼和檢查狀態。
- 未確認的資料預設保留在乾淨資料，由檢查狀態決定，可選只輸出已確認。

## 資訊安全（2026-11-09 review）
- 本機服務只接受 Host 為 127.0.0.1／localhost 的請求（擋 DNS rebinding）；`/api/` 拒絕跨站的 Sec-Fetch-Site 與不符的 Origin（擋 CSRF）。
- 回應加 CSP、X-Frame-Options、nosniff、Referrer-Policy、CORP/COOP；API 回應 no-store，頁面圖片只允許 private 快取。
- 錯誤只回一般訊息，例外細節寫進 `workspace/logs/pdfmapper.log`。`/api/ping` 只回路徑雜湊，不外洩本機路徑。
- 日誌原則：只記 doc_id、run_id、範本代號與數量；不記檔名（指令列用檔名雜湊）、PDF 內容、抓到或人工修正的值。輪替 1 MB × 5 份，30 天以上刪除。外部字串去控制字元，避免偽造日誌行。
- 上傳檢查 `%PDF-` 檔頭，檔名去掉路徑、控制字元與 Windows 不允許的字元；範本代號限 64 字並排除 Windows 保留名稱。
- 背景解析逐份 try/except，一份失敗不會讓整批卡在「解析中」；最多保留 20 次解析結果。
- Excel 所有文字儲存格統一去控制字元並強制文字格式（防公式注入，包含檔名與整份檢查訊息）。
- 啟動程式下載 uv 後比對官方 SHA256，不符就停止。升級 uv 版本時要同步更新雜湊。
- 處理上限（2026-11-10，回應外部 code review 3.1、3.2）：集中在 `app/pdfmapper/limits.py`。
  - 頁數上限 1000 頁，開檔時先數頁數，超過就不建立頁面資料。
  - 單檔時間上限 15 分鐘，在頁、欄位、表格之間檢查，超過只停這一份，其他檔案照常。多範本比較共用同一個期限。
  - 渲染圖整份文件最多留 6 張（原本每頁各留 2 張直到關檔，100 頁掃描檔做 OCR 約累積 2.6 GB）；單頁超過 4000 萬像素時自動降解析度。
  - 正規表達式：範本儲存與載入時擋「無上限的重複裡又有重複，且沒有固定字元隔開」的寫法，例如 `(a+)+`、`(\w+\s?)+`，並限 500 字。單一個正規表達式卡住時無法從中間打斷，所以靠事前檢查。不改用支援逾時的 `regex` 套件，避免多一個要離線打包的相依。`(a|aa)+` 這類靠選項重疊的寫法偵測不到，風險接受。
  - 不做的：限制比對文字長度（儲存格本來就短，截斷反而會改變取值結果）；用子行程強制中止（每個行程都要重新載入 OCR 模型，Windows 上成本高）。
- 發布與更新的完整性（2026-11-10 review）：
  - 安裝新版前，ZIP 必須和同資料夾的 `SHA256SUMS*.txt` 相符（瀏覽器重複下載的核對檔都會找，任一份相符即可），詢問時顯示雜湊。擋下載不完整、拿錯檔案、改名冒充的 ZIP。採最小改動：核對檔和 ZIP 來自同一個 Release 頁，擋不住能改 Release 的人；要防這一層得加簽章，目前不做。
  - 打包時每個離線套件都要和 `uv.lock` 的 SHA256 相符，鏡像或 PyPI 上的檔案被換掉就不發布。同事端不另外 `--require-hashes`，因為清單和套件在同一個 ZIP 裡，已由 ZIP 的核對涵蓋。
  - 啟動用 `python -P`，工具資料夾裡的同名 `.py` 不會被誤載入。
- 保留現狀：匯出仍在 `workspace/output` 留一份（手冊既有功能）；`--post` 會執行指定腳本（第 3 層設計）。

## 發布、更新與資料夾分工（2026-11-10）
- 不包成 exe。PyInstaller 這類打包常被防毒誤判，每次啟動要解壓到暫存，也不能只更新一部分。資料夾加啟動腳本比較透明，IT 也容易審核。
- 資料夾分三塊：`app/` 是程式，更新整包換；`workspace/` 是使用者資料，更新不動；`runtime/` 放 uv、Python 與套件，可隨時刪掉重建。所有路徑集中在 `app/pdfmapper/paths.py`，啟動程式用 `PDFMAPPER_HOME` 指定最外層。
- `run.bat` 只有一行並以 `exit /b` 結尾。cmd 執行批次檔時是一行一行讀，整行讀完才執行，更新時覆蓋 `run.bat` 才不會接著讀到新檔案的內容。
- 發布走 GitLab Release。同事下載 ZIP 後不用解壓，直接放進工具資料夾，雙擊 `run.bat` 就會偵測並詢問安裝。這樣不需要共用資料夾，也不用在同事電腦存 GitLab token。
- 不做連網自動檢查：同事的電腦通常連不到需要登入的 GitLab，也沒有共用位置可放版本資訊。改成把手動步驟寫清楚，使用手冊附圖解，並保留自動換版失敗時的手動更新方式。
- 只在雙擊開啟時找新版 ZIP；指令列模式不檢查也不暫停，才能放進排程。
- 從網路下載的 ZIP 會被 Windows 標成「來自網路」。第一次安裝要使用者解除封鎖；之後由 `run.bat` 用 PowerShell 解壓安裝，不會再遇到。
- 安裝順序：解壓、確認版本與檔名一致，才把 `app` 改名成 `app.old`、新版移入。中途失敗就換回原狀。保留一份 `app.old` 給使用者自行 `rollback`。
- 全面退回不靠 rollback：啟動程式只會往新版更新，要讓所有人回到舊行為，就發一個還原修改的新版本。
- 要所有人更新或暫停使用時，由負責人直接通知。
- 發布包附 Windows 64 位元的套件檔（`app/wheels`），用 `uv pip sync` 讓環境和清單完全一致，舊版多出的套件會移除。使用者不需要連到 PyPI，只有第一次要從 GitHub 下載 uv 和 Python。
- 版本號只寫在 `app/pyproject.toml`。程式、啟動腳本、CI 都讀它；打標籤時 CI 會比對標籤和版本，CHANGELOG 沒有這一版的段落就不能發布。
- 0.1 版的 `templates`、`custom`、`output` 與 `.tools` 會在第一次啟動時複製或搬到新位置，只複製不刪除，由使用者確認後自行刪掉。
- 示範範本只在第一次建立 `workspace/templates` 時放入，使用者刪掉後不會再出現。

## CI 與公司網路（2026-11-10）
- 公司 runner 常常連不到 pypi.org。`uv sync --frozen` 會照 `uv.lock` 記的 pypi.org 網址下載，設定鏡像也沒用，所以 CI 改成 `uv export`（含 SHA256）再 `uv pip install --require-hashes`，來源由 `PIP_MIRROR` 決定，檔案仍和 lock 完全相同。
- 每個 job 開頭用 `scripts/ci_env.sh` 先連一次套件來源，連不到就用中文說明要找 IT 要什麼，不讓使用者看到難懂的錯誤。
- 全部 job 只用一個映像檔（ghcr.io 的 uv）。上傳與建立 Release 改用 Python 標準函式庫（`scripts/publish_release.py`），不再拉 Docker Hub 的 curl 和 registry.gitlab.com 的 release-cli，要請 IT 放行或鏡像的東西只剩一個。
- `uv lock --check` 不需要網路，但設了鏡像時 uv 會因為鏡像網址和 lock 記的 pypi.org 不同而誤判要更新，所以檢查時暫時拿掉鏡像設定並加 `--offline`。
- 弱點檢查不放在 CI：資料庫在 pypi.org，公司鏡像沒有，一直失敗的 job 只會讓人習慣忽略紅燈。改成發版前與每月在自己的電腦執行 `scripts/audit.py`，列在發版檢查清單。PDF 是不受信任的輸入，pdfium、pdfminer、Pillow、OpenCV 都有過弱點，所以檢查本身不能省。
- 測試用的範例掃描檔要畫中文，CI 映像檔沒有中文字型。專案內附 Noto Sans CJK TC 的子集（`tests/fonts`，OFL 授權，只含範例與測試用到的字，約 190 KB），每台電腦和 CI 畫出來的範例都一樣。不打包進發布包。
- 沒有鏡像時的退路：在自己的電腦打包，手動建立 Release。

## 治理
- 負責人、備援人、處理的資料與出問題時的做法記在 `OWNER.md`。
- 刻意只留大架構：工具卡、發版檢查清單、維護手冊。不寫各公司不同的政策或登記流程，公司另有規定時以公司為準。
- 每次發版依 `docs/security-checklist.md` 勾選；CI 自動做測試、`uv lock --check` 與打包驗證，弱點檢查在本機執行 `scripts/audit.py`。

## 環境
- 用 uv 建立，uv、Python 3.12 和套件都放在 `runtime/`，不裝進系統 Python，也不需要先安裝 Python。
- 依賴定義在 `app/pyproject.toml`，版本鎖在 `app/uv.lock`。
- 發布包的離線套件走 `uv pip sync --no-index --find-links`，因為 `uv sync --frozen` 不吃 `--find-links`。

## 資源釋放
- 所有頁面關閉後程式自動結束，正在解析時會等解析完。
- 已開著時再啟動，只開啟原本的工具。
- 上傳的 PDF 暫存在結束時清除，異常結束則在下次啟動時清除。

## 待確認
- 真實資料：續頁版面、文字層品質、貨物名稱長度與跨頁列的實際行為。
- 同一格同一個 key 出現多次、一格多個 sub 要拆成多列：尚未支援。
- 影像型 PDF 的跨欄內容：逐欄辨識會切到長文字，目前只能標記。
- 分隔線整份都放偏時，吃進來的內容每一行都有，會被當成這欄的格式而不標記搶欄；目前靠隔壁欄空白或必填缺值發現。
- 值很短（一兩個字）時，用文字判斷值用到哪幾行可能誤認，偏向多標記。
- 結果表格的儲存格不在字中間折行，很長的中文貨名可能讓欄位變寬，要用真實資料看。
- 真正的 Windows：啟動與更新流程只在 Linux 版 PowerShell 測過。
